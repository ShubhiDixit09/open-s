For each future PR, add a separate Markdown file here and a row above. Use a concrete title about the problem solved. The post should explain the actual setup, the data used with permission, one useful question, the result obtained, what failed and what remains limited.

The [proposal index](../proposals/README.md) links all five published GitHub issues and their saved issue texts. The blogs remain working drafts until real work supplies the usage and test evidence.

Keep planned behavior separate from observed results. Capture the exact versions, commands, screenshots or redacted output while testing; that evidence makes the later writing specific and accurate. Do not write invented first-person anecdotes, benchmark numbers, test results or claims of live usage.

AI-assisted drafts are editing aids. Shubhi should review technical claims, contribute her actual experience and revise the final language herself to respect the [event's originality and AI-use rules](https://www.wemakedevs.org/hackathons/mergetober/rules). Use plain language, specific evidence and transparent attribution of assistance.

Before publication, confirm that installation works from a clean environment, the example commands were actually run, the PR URL is correct, and the article includes the limitations discovered during real use. Record the public URL here after publishing.
